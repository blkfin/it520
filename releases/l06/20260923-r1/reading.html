Reading a scanner report

What the count means. In this simplified workflow, each successful scan records one item added to the current tote. The packing app keeps the running tote count: start at 0, add 1 per item, reset to 0 for a new tote. Busy means the worker is filling the tote. Updates also report status changes, so Updating does not imply another scan.

A bit is a binary digit, 0 or 1. Several bits form a pattern. The pattern has no built-in meaning: a rule gives it meaning.

States use a codebook

A codebook assigns each pattern to one mutually exclusive scanner state.

000Ready
001Busy

Counts use place value

In decimal, 13 is 1 × 10 + 3 × 1. Position determines each digit’s contribution. Binary keeps this rule with different place values: 8, 4, 2, 1. For an unsigned integer, each place is worth twice the place to its right. Add the weights under the 1s.

weight8421
bit1101
adds8401

1101 = 8 + 4 + 0 + 1 = 13

Width sets capacity

Each extra bit doubles the patterns. A width of n bits gives 2n patterns. If those patterns are unsigned numbers starting at zero, the largest value is 2n − 1. Four bits give 16 patterns and values 0–15; five give 32 patterns and values 0–31.

A byte is eight bits. The layout says which bits belong to each field. Field width and report size are different quantities.

Hex is shorter notation for the same bits

One hexadecimal character stands for exactly four bits. 2D is 0010 1101. The left hex character spans bits 7–4; the right spans bits 3–0. Those four-bit groups are not the field boundaries: use the layout.

Read 2D: status bits 7–5 are 001, so the codebook says Busy. Count bits 3–0 are 1101, so place value says 13 items recorded in the current tote.

Read an existing report: expand the hex notation, then find the field's position, note its width, then apply its rule. Design a new field: compare required meanings with available patterns. For 19 zones, four bits give only 16 patterns; five give 32, enough. If the format changes, both ends must agree.
